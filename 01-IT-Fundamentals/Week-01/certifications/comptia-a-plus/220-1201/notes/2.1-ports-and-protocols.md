## Part 1: Introduction to IP

### The Networking Analogy
- **Network** = the road / highway
- **IP (Internet Protocol)** = the truck that carries the data
- **TCP / UDP** = the boxes inside the truck
- **Application data** (HTTP, etc.) = the contents of the boxes

### Encapsulation & Decapsulation
Data is nested (encapsulated) as it travels:

```
Ethernet Frame
└── IP Header + IP Payload
    └── TCP/UDP Header + TCP/UDP Payload
        └── Application Data (HTTP, SSH, etc.)
```

### TCP vs UDP

| Feature                  | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol)      |
|--------------------------|-------------------------------------|-----------------------------------|
| Connection type          | Connection-oriented                 | Connectionless                    |
| Reliability              | Reliable (acknowledgments)          | Unreliable (no acknowledgments)   |
| Error recovery           | Yes (retransmission)                | No                                |
| Flow control             | Yes                                 | No                                |
| Overhead                 | Higher                              | Very low                          |
| Best for                 | Web, email, file transfer, SSH      | VoIP, video, streaming, DHCP, TFTP|

**TCP** = formal setup + teardown (like a phone call) + acknowledgments + flow control  
**UDP** = “fire and forget” – best effort delivery

### Port Numbers
- Every service on a device is identified by a **port number**
- Range: **0 – 65,535**
- **Well-known / Non-ephemeral ports**: 0 – 1023 (used by servers)
- **Ephemeral ports**: 1024 – 65535 (temporary ports used by clients)

**Important**:  
TCP port 80 ≠ UDP port 80 (they are completely separate)

A full conversation needs:
1. Source IP address
2. Destination IP address
3. Protocol (TCP or UDP)
4. Source port (usually ephemeral)
5. Destination port (usually well-known)

## Part 2: Common Ports (Must Memorize)

| Port(s)          | Protocol     | Name                          | Purpose / Notes                                      |
|------------------|--------------|-------------------------------|------------------------------------------------------|
| **20 / 21**      | TCP          | FTP                           | File Transfer Protocol (20 = data, 21 = control)     |
| **22**           | TCP          | SSH                           | Secure Shell – encrypted remote command line         |
| **23**           | TCP          | Telnet                        | Unencrypted remote command line (avoid!)             |
| **25**           | TCP          | SMTP                          | Simple Mail Transfer Protocol (sending email)        |
| **53**           | UDP (mainly) | DNS                           | Domain Name System – name ↔ IP resolution            |
| **67 / 68**      | UDP          | DHCP                          | Dynamic Host Configuration Protocol                  |
| **80**           | TCP          | HTTP                          | Hypertext Transfer Protocol (unencrypted web)        |
| **110**          | TCP          | POP3                          | Post Office Protocol v3 (receiving email)            |
| **143**          | TCP          | IMAP                          | Internet Message Access Protocol (better than POP3)  |
| **443**          | TCP          | HTTPS                         | HTTP Secure (encrypted web)                          |
| **445**          | TCP          | SMB / CIFS                    | Server Message Block (Windows file/printer sharing)  |
| **389**          | TCP          | LDAP                          | Lightweight Directory Access Protocol                |
| **3389**         | TCP          | RDP                           | Remote Desktop Protocol                              |

### Extra Important Notes
- **FTP** can use anonymous login or require credentials
- **SSH** should always be preferred over Telnet
- **DNS** is critical – almost everything relies on it
- **DHCP** automatically assigns IP, subnet mask, gateway, DNS
- **SMB** (port 445) is the modern Windows file sharing protocol (older NetBIOS used 137/139)
- **RDP** allows full remote desktop control of Windows machines

---

## Key Takeaways
- IP moves the data, TCP/UDP decides *how* it is moved
- TCP = reliable, UDP = fast & lightweight
- Port numbers tell the OS which application should receive the data
- You **must** know the common ports listed above for the exam and real-world troubleshooting
- Firewalls filter traffic primarily by IP + port + protocol
