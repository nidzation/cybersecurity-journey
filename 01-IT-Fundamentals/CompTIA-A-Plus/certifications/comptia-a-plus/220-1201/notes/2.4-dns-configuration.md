# 2.4 DNS Configuration - Professor Messer (CompTIA A+ 220-1201)

## Overview
DNS (Domain Name System) is one of the most critical services on any network. It translates human-readable names into IP addresses and provides many other important functions.

---

## How DNS Works

### Hierarchy
DNS is a **distributed hierarchical database**:

```
Root Servers (13 clusters, 1000+ servers)
└── Top-Level Domains (TLDs)
    ├── Generic: .com, .org, .net, etc.
    └── Country codes: .us, .uk, .ca, etc. (~275)
        └── Domain (e.g. professormesser.com)
            └── Subdomains / Hosts (www, mail, ftp, etc.)
```

### Common Tools
| Tool        | Platform          | Purpose                          |
|-------------|-------------------|----------------------------------|
| `dig`       | Linux / macOS     | Detailed DNS queries             |
| `nslookup`  | Windows / others  | Simple DNS lookups               |

Example:
```bash
dig www.professormesser.com
nslookup professormesser.com
```

## Important DNS Record Types

### A Record
- Maps a hostname to an **IPv4** address
- Example: `www.professormesser.com → 162.159.246.164`

### AAAA Record (Quad-A)
- Maps a hostname to an **IPv6** address

### CNAME Record (Canonical Name)
- Creates an **alias** for another hostname
- Useful when one server has multiple names (www, ftp, chat, etc.)
- Change the A record once → all CNAMEs automatically update

### MX Record (Mail Exchanger)
- Tells other servers **where to send email** for your domain
- Points to a mail server hostname (which then has an A/AAAA record)

### TXT Record
- Stores human-readable text
- Common uses:
  - Domain verification
  - Email authentication (SPF, DKIM, DMARC)

---

## Email Authentication Records (Very Important)

### SPF (Sender Policy Framework)
- Lists which servers are allowed to send email for your domain
- Helps prevent spoofing / spam

### DKIM (DomainKeys Identified Mail)
- Uses public/private key cryptography
- Email server signs outgoing messages with private key
- Receiving server checks the public key in DNS (TXT record)
- Proves the message was not altered and really came from your domain

### DMARC (Domain-based Message Authentication, Reporting & Conformance)
- Tells receiving servers **what to do** if SPF or DKIM fails
- Options: none, quarantine (spam folder), or reject
- Can also send reports back to the domain owner

---

## Key Concepts

- **TTL (Time To Live)**: How long a record is cached (e.g. 15 minutes)
- Lower TTL = faster updates, higher DNS load
- Higher TTL = less load, slower propagation of changes

- DNS is **critical** — a single mistake can take services offline
- Always have a backup and a way to quickly revert changes

---

## Key Takeaways
- DNS is a hierarchical, distributed system
- A / AAAA records = IP addresses
- CNAME = aliases
- MX = email delivery
- TXT records power modern email security (SPF + DKIM + DMARC)
- Always be careful when editing DNS — small mistakes can cause big outages
